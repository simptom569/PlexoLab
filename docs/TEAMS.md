# PlexoLab: команды, личная команда, видимость проектов. Как это будет работать

Описание **утверждено владельцем 2026-10-28** (решения 2026-10-21…28; вариант Б переключателя выбран). Это источник правды для командного уровня над проектами. Где он расходится с `PROJECTS.md` (общая вики, «команда» в разделе 7), прав этот файл.

По мере реализации актуальная схема и API переносятся в `DATA-MODEL.md`; этапы К1–К3 описаны в `ROADMAP.md`.

---

## 0. Коротко

- Каждый проект принадлежит **одной команде**. Проектов «без команды» нет.
- У каждого человека с момента появления аккаунта есть **личная команда «Личное»**. Это обычная команда: в неё можно приглашать людей, в ней есть вики и файлы. Отличие только в защитах (4.2).
- Команда даёт: **вики, библиотеку файлов, список людей, место для проектов**.
- Проект имеет **видимость**: «Только участники» или «Вся команда».
- **Администратор команды видит все проекты команды и всегда администратор в них.**
- **В любой проект можно позвать любого человека по e-mail**, состоять в команде для этого не нужно. Кто в проекте, но не в команде проекта, называется **гостем**.
- Гость вики команды **читает только если админ команды включил** настройку «Гости проектов могут читать вики команды» (по умолчанию выключено). Писать гость не может никогда.
- Один человек может состоять в нескольких командах. Команды создаёт любой.
- Зачем сейчас: регистрация будет открытая. Пока вики, файлы и список людей общие на весь сервер, новый человек читал бы всё это. С командами новичок видит только свою пустую «Личное».
- Порядок работ: команды (К1–К3), регистрация и почта, этап 9, этап 10, Н5 (2026-10-29 Н5, трей, автозапуск, один запуск и память окна сделаны раньше, по просьбе владельца).

## 1. Понятия

| Понятие | Что это |
|---|---|
| **Аккаунт** | Человек с e-mail и паролем. Сейчас создаётся командой `server user add`, после этапа регистрации сам. |
| **Команда** | Группа людей с общей вики и библиотекой файлов. Название, участники, роли (3.1). |
| **Личная команда** | Команда «Личное», которая создаётся вместе с аккаунтом (4.2). |
| **Проект** | Принадлежит одной команде. Участники, роли, видимость. |
| **Явный участник проекта** | Состоит в списке участников проекта с ролью «администратор» или «участник». Попадает туда по приглашению или как создатель. |
| **Неявный участник** | Член команды в проекте «Вся команда», которого нет в списке. Работает как «участник». |
| **Гость** | Явный участник проекта, который не состоит в команде этого проекта. |
| **Администратор сервера** | Человек с флагом `is_admin` (9). |

Слово «пространство» не используется: в приложении везде «команда». Исключение: подпись «Рабочее пространство» из макета.

**Пример.** Лена создаёт команду «Веб». В ней проект «Сайт» с видимостью «Только участники» и общая вики. Артём в команде «Веб», Игорь (подрядчик) нет. Лена зовёт Игоря в «Сайт» по e-mail. Игорь принимает и становится гостем: видит доску «Сайта», комментирует, получает задачи. Вики «Веб» Игорь не видит, пока Лена как админ команды не включит «Гости проектов могут читать вики команды». Других проектов «Веб» и списка людей команды у Игоря нет. Артём в «Сайт» не попадает, пока Лена не позовёт его или не переключит видимость на «Вся команда». Свои проекты Игорь ведёт в своей «Личное», где администратор Игорь.

## 3. Доступ и права

### 3.1 Роли команды

- **Администратор команды.** Создатель становится им автоматически. Может быть несколько.
- **Участник команды.**

Других ролей нет.

### 3.2 Роли проекта

**Администратор** и **участник**. Гость это не роль, а положение: у него в проекте роль «администратор» или «участник».

### 3.3 Правило доступа к проекту

Одно правило, одна функция на сервере (`access::project`):

**доступ = явный участник ИЛИ администратор команды ИЛИ (видимость «Вся команда» И член команды)**, и команда не в архиве. Администратор сервера сверх этого (9).

**Роль в проекте = высшая из оснований.** Администратор команды и явный админ проекта это «администратор»; остальные «участник».

### 3.4 Видимость проекта

| | Только участники | Вся команда |
|---|---|---|
| Кто видит и работает | явные участники и администраторы команды | явные участники и **все члены команды** |
| Роль члена команды, которого нет в списке | | «участник» |
| Админ проекта | явный, или администратор команды | то же |
| Гости | по приглашению | по приглашению |

Правила:

- **По умолчанию** у нового проекта «Только участники»; выбирается при создании.
- **Менять видимость** может только админ проекта (и администратор команды как админ проекта, и администратор сервера).
- **Смена с подтверждением**, число считает сервер (окно в стиле «У N задач изменятся id»):
  - на «Вся команда»: «Проект увидят N членов команды»;
  - на «Только участники»: «Доступ потеряют N человек: их нет в списке участников». В N не входят администраторы команды: они сохраняют доступ.
- Выход или исключение человека из команды убирает его неявный доступ сразу.
- **Люди проекта** (исполнитель задачи, ответственный модуля, @упоминания, фильтр «Участник» в ленте): явные участники, плюс при «Вся команда» все члены команды. Администраторы команды попадают в эти списки, только если они явные участники или проект «Вся команда».
- **Окно «Участники» проекта** показывает:
  - явных участников;
  - администраторов команды с пометкой «Администратор команды» (без кнопки «убрать»: админы проекта видят, что есть админ выше);
  - при «Вся команда» всех членов команды отдельными строками. У неявной строки «убрать» неактивна (подсказка: «Доступ у всей команды. Чтобы убрать, выберите «Только участники»»), роль можно повысить: повышение до админа создаёт явную запись сразу, **без приглашения**. Если человек и явный, и неявный, одна строка с высшей ролью.
- **«Выйти из проекта»** есть только у тех, кто этим теряет доступ: не у администраторов команды и не у членов команды в проекте «Вся команда».
- **Секретный проект от администраторов команды сделать нельзя.** Если когда-нибудь понадобится, нужен третий режим; сейчас его нет.

### 3.5 Права в команде

| Действие | Админ команды | Участник команды | Гость проекта | Посторонний |
|---|---|---|---|---|
| Знать, что команда есть, и её название | да | да | только название: строка «Студия · гость» в переключателе | нет |
| Читать вики и библиотеку | да | да | только если включено «Гости проектов могут читать вики» | нет |
| Править вики, загружать и удалять файлы и папки | да | да | нет, никогда | нет |
| Видеть список людей команды | да | да | нет | нет |
| Создавать проект в команде | да | да | нет | нет |
| Видеть проекты команды | все | свои и «Вся команда» | только свои | нет |
| Приглашать в команду, отзывать приглашения | да | нет | нет | нет |
| Убирать из команды, менять роли в команде | да | нет | нет | нет |
| Переименовывать команду, менять настройку для гостей, архивировать (кроме личной) | да | нет | нет | нет |
| Выйти из команды | да, если не последний админ и не владелец «Личное» | да | | |

### 3.6 Права в проекте

| Действие | Админ проекта (явный или администратор команды) | Участник проекта (явный или неявный) |
|---|---|---|
| Работать (доска, бэклог, модули, релизы, документы, ссылки, лента, комментарии) | да | да |
| Создавать метку из окна задачи | да | да |
| Менять название, цвет, ключ, видимость; править и удалять метки | да | нет |
| Приглашать, отзывать, убирать людей, менять роли | да | нет |
| Архивировать и возвращать | да | нет |

Гость это явный участник: права по его роли те же.

## 4. Команды

### 4.1 Обычная команда

- Создать может **любой**. Создатель становится администратором.
- Поле одно: **название** (1–60 знаков). Названия не уникальны.
- **Лимит:** один человек создаёт не более **5** обычных команд (число меняется настройкой сервера). «Личное» не считается.

### 4.2 Личная команда «Личное»

- **Создаётся автоматически**, когда появляется аккаунт: `server user add` и будущая регистрация делают это в одной операции с аккаунтом. Существующим аккаунтам её создаёт миграция.
- Называется **«Личное»**, переименовывается как любая.
- Владелец (чья она) её администратор.
- **Защиты:** её нельзя архивировать; владелец не может из неё выйти, быть убранным или понижен в роли; она не считается в лимит команд.
- Остальное как у обычной: приглашать людей, делать их администраторами, вики, файлы, проекты. Приглашённые могут выйти.
- Когда в «Личное» пригласили людей, она становится общей, но называться «Личное» продолжает, пока владелец не переименует.
- В переключателе она первая; при первом входе выбрана именно она.

### 4.3 Окно «Настройки команды» (в стиле «Настроек проекта»)

Для админа команды, три вкладки:

- **Основное:** название; переключатель **«Гости проектов могут читать вики команды»** (выключен по умолчанию, и для «Личное» тоже).
- **Участники:** список (аватар, имя, роль, «убрать»), ожидающие приглашения, поле «пригласить по e-mail» и выбор роли (по умолчанию «Участник»). Под полем одна строка: «Администраторы команды видят все её проекты».
- **Архив:** кнопка «Архивировать команду» с подтверждением. У «Личное» вкладки нет.

Участнику команды вместо настроек в меню: «Участники» (только список) и «Выйти из команды».

### 4.4 Выход и исключение

- Участник выходит сам (с подтверждением). Админ убирает другого.
- **Выход или исключение убирает человека из всех явных участий в проектах этой команды** (как в организации на GitHub). Неявный доступ «Вся команда» пропадает сам. **Гостей это не затрагивает**: из команды их никто не убирает.
- Имя ушедшего остаётся на старых задачах, комментариях, в ленте и в авторстве страниц вики.
- **Последний админ команды** не может выйти, понизить себя или быть убранным: «Вы единственный администратор. Назначьте другого или архивируйте команду».
- **Блокировки «единственный админ проекта» нет**: проект не остаётся без администратора, потому что у команды всегда есть админ, а у «Личное» владелец неудаляем.
- Вернуться в команду можно только по новому приглашению. Прежние проекты заново открывают их администраторы.

### 4.5 Архив команды

- Команда **не удаляется**, её можно только архивировать (админ команды, личную нельзя). Возвращает админ команды.
- Архивная команда исчезает из переключателя; её вики, файлы и **все её проекты, включая гостевые**, недоступны всем, пока команду не вернули. Данные целы.
- Вернуть: окно «Архив проектов» в меню пользователя получает второй раздел «Команды».

### 4.6 Чего команда не умеет (пока)

Вложенных команд, передачи команды другому, удаления команды, прав на отдельные страницы вики, переноса проекта между командами (отложено), «секретных» проектов нет.

## 5. Проекты

### 5.1 Создание

- «+» при наведении на заголовок «Проекты» создаёт проект **в выбранной сейчас команде**. В гостевой команде «+» нет.
- Окно «Новый проект»: название, цвет, ключ (необязательно), **Видимость** («Только участники» / «Вся команда»), строка «Команда: Веб» показывает, куда создаётся. Поле «Видимость» делается из тех же компонентов, что остальные окна проекта (`seg`, строки «Настройки проекта»).
- Создатель становится администратором проекта.
- Создать проект в команде может любой её член.

### 5.2 Что показывает сайдбар

- В **своей** команде (я член): проекты, где я явный участник, плюс все проекты с видимостью «Вся команда». **Администратор команды видит все проекты команды.** Архивные скрыты.
- В **чужой** команде, где я только гость: проекты, где меня позвали.
- Проект показывается только в команде, которой принадлежит.

### 5.3 Гость

- Делает в проекте всё, что разрешает его роль.
- **Не видит:** список людей команды, остальные проекты команды.
- **Вики и библиотека:** только при включённой настройке команды. Включена: читает и скачивает страницы вики и файлы библиотеки, видит события вики в ленте проекта и метки «кто в каком блоке», ищет по названиям страниц и файлов; не загружает, не удаляет, не создаёт папки, не пишет в страницы. Выключена: пункта «Вики», библиотеки и событий вики для него нет.
- Видит название команды и участников этого проекта.
- Если гостя приглашают в команду и он принимает, он перестаёт быть гостем сам. Роль в проекте остаётся.

### 5.4 Выход, архив, перенос

- Выход и архив проекта как раньше. Архив команды скрывает все её проекты разом.
- **Перенос проекта в другую команду отложен.** Если делать: меняется `team_id`; явные участники, не члены новой команды, становятся гостями; видимость сбрасывается на «Только участники»; события вики старой команды пропадают из ленты.

## 6. Приглашения

| Куда | Кто приглашает | Кого | Кто решает |
|---|---|---|---|
| В команду | админ команды | любой аккаунт по e-mail | приглашённый |
| В проект | админ проекта | любой аккаунт по e-mail, команда не важна | приглашённый |

- Приглашения обоих видов лежат в одном окне «Приглашения» в меню пользователя: разделы «Команды» и «Проекты». Счётчик у пункта и точка у имени считают **неотвеченные приглашения обоих видов**.
- Приглашения в команду и в её проект **не связаны**: приняв одно, человек не получает другое. Одним действием «в команду и сразу в проект» не приглашаем.
- Член команды в проекте «Вся команда» уже имеет доступ; приглашать его нужно только чтобы сделать админом, но проще повысить роль в окне «Участники» (3.4).
- Приглашения не истекают, пока их не приняли, не отклонили или не отозвали. Приглашения в архивные команды и проекты скрыты.
- Повторное приглашение: «Уже в команде» / «Уже в проекте» / «Уже приглашён».
- Адрес без аккаунта не ошибка: приглашение сохраняется вместе с адресом, ответ тот же («Приглашение отправлено»), в списке ожидающих у администратора строка «ждёт регистрации» (вместо имени адрес). Когда аккаунт с таким адресом появляется (`server user add`, сид, регистрация), триггер `users_claim_invites` делает такие приглашения обычными: они сразу видны человеку в «Приглашениях», решает он сам. Отозванные и закрытые не переходят. Адрес без «@» или точки в домене: 400 «Некорректный e-mail». **Для регистрации:** новый аккаунт забирает чужие приглашения в момент создания строки в `users`, поэтому регистрация обязана создавать её только после подтверждения адреса (код из письма), иначе чужой адрес позволит забрать чужие приглашения.
- Нынешние пользователи при миграции становятся участниками общей команды и всех её проектов, без приглашений.

## 7. Вики и библиотека файлов

- **Принадлежат команде**; есть у каждой, в том числе у «Личное». Экран «Вики» включает и библиотеку файлов.
- Читать и править могут все члены команды (прав на отдельные страницы нет). Гости: 5.3.
- События вики и файлов пишутся **с командой**, а не «ни с чем», как сейчас.
- **Лента проекта.** В ленту проекта подмешиваются события вики его команды для членов команды и для гостей при включённой настройке.
- **Названия папок библиотеки** уникальны **внутри команды** (сейчас `folders.name unique` на весь сервер).
- **Вложения задач** привязаны к задаче и проекту; в библиотеку не попадают (как сейчас).
- **Поиск** (Ctrl+K) идёт по выбранной команде: задачи и документы её проектов, вики и файлы команды. Задачу по id (`WEB-141`) из другой команды в поиске не найти, пока не переключить команду; клик по уведомлению или приглашению из другой команды переключает команду сам.

## 8. Люди и e-mail

- **Приглашать можно любого по e-mail**; список людей для этого не нужен.
- Но `GET /users` нужен клиенту как «книга имён и аватарок»: имя исполнителя, автора комментария, автора события в ленте, того, кто загрузил файл или назначил задачу. Поэтому в неё попадают **люди из моих команд и все, кто есть в моих проектах** (включая гостей и ушедших, чьи имена остались на видимых мне данных). Способ реализации выберу в К1.
- **E-mail виден:** самому человеку; администратору команды у всех членов его команды; админу проекта только у тех, кого он сам пригласил или кто в явном списке проекта. У неявных членов команды e-mail скрыт. Администратору сервера виден всем (9).
- Поле `is_admin` другим людям не отдаётся.

| Что | Значение |

**Принятые риски** (решение владельца):

- Ограничения числа попыток входа нет; срок токена доступа до 12 часов (прежнее решение).
- Администратор сервера читает всё.
- До этапа 10 сервер на http.

## 12. Данные и миграция

### 12.1 Схема

Новые таблицы:

- `teams`: id, название, создатель, `personal_for` (необязательный, ссылка на человека, **уникальный**), `guests_read_wiki` (по умолчанию `false`), `archived_at`, `created_at`.
- `team_members`: команда, человек, роль `admin` / `member`, `created_at`; ключ (команда, человек); индекс по человеку.
- `team_invites`: как `project_invites` (приглашённый, пригласивший, роль, статус `pending` / `accepted` / `declined` / `revoked`), одно ожидающее на пару.

Изменяются:

- `projects.team_id` **обязательный**, `on delete restrict`; `projects.visibility` (`members` / `team`), по умолчанию `members`.
- `wiki_pages.team_id`, `folders.team_id`, `files.team_id` (файлы библиотеки и вложения вики) обязательные; у `folders` уникально (команда, название).
- `activity.team_id` необязательный (события вики и файлов).
- `project_invites`: с регистрацией `user_id` станет необязательным и появится `email` (этап регистрации).

Метки, документы, ссылки, ключи, комментарии, уведомления не меняются. Индексы: `team_members(человек)`, `projects(команда)`.

### 12.2 Как нынешние данные переезжают

1. Создаётся **общая команда «Dream Team»** (переименовывается потом).
2. В неё входят **все нынешние аккаунты**: `is_admin` администраторами команды, остальные участниками.
3. Все проекты получают эту команду, видимость «Только участники» (членство в проектах не меняется).
4. Вся вики, папки, файлы библиотеки и события вики получают эту команду.
5. **Каждому нынешнему аккаунту создаётся «Личное»**, он её администратор.

Обратная миграция в `server/migrations_down/`: убирает таблицы и колонки; если при этом окажутся две папки с одним названием из разных команд, откат остановится, а не потеряет данные.

**Перед боевой миграцией нужна резервная копия базы:** доступа к серверу у меня нет.

## 13. API

Все адреса под `/api/v1`, каждый обязан попасть в тест-обход с пометкой доступа.

**Новые:**

| Метод и адрес | Доступ |
|---|---|
| `GET /teams` | открыт: мои команды и команды, где я гость (у гостевых только id, название, пометка `guest`) |
| `POST /teams` | открыт (создать) |
| `GET /teams/{id}`, `GET /teams/{id}/members` | члены |
| `PATCH /teams/{id}` (название, `guests_read_wiki`) | админ команды |
| `POST /teams/{id}/archive`, `.../restore` | админ команды (личную нельзя) |
| `PATCH /teams/{id}/members/{user}`, `DELETE ...` | админ команды |
| `POST /teams/{id}/leave` | члены |
| `POST /teams/{id}/invites`, `DELETE /team-invites/{id}` | админ команды |
| `GET /team-invites`, `POST /team-invites/{id}/accept`, `/decline` | только про меня |
| `GET /teams/{id}/wiki`, `POST ...`, `GET/POST /teams/{id}/files`, `/teams/{id}/folders` | чтение: члены и гости при включённой настройке; запись: члены |
| `GET /projects/{id}/visibility-impact?to=...` | админ проекта: сколько человек затронет смена |
| `GET /admin/teams?q=...` | только `is_admin` («Все команды сервера») |

**Меняются:**

- `POST /projects` принимает обязательные `team_id` и `visibility`. Не член команды (и не администратор сервера) получает «не найдено».
- `PATCH /projects/{id}` принимает `visibility`.
- `GET /projects` отдаёт `team_id`, `visibility`, признак «я гость».
- `GET /users` по разделу 8.
- Адреса по записи (`/wiki/{id}`, `/files/{id}`, `/folders/{id}`): команда находится по записи.
- `GET /search` получает параметр команды.
- `GET /projects/{id}/activity` показывает события вики членам команды и гостям при включённой настройке.
- Создание аккаунта (`server user add`, регистрация) создаёт «Личное».

**События WebSocket.** Новая аудитория `Team(команда)` для вики и файлов (члены, плюс гости при включённой настройке); `team.changed` для членов команды; адресное `team-invite.changed`; `project.changed` шлётся и при смене видимости. Список проектов, события которых получает соединение (`visible` в `ws.rs`), включает: явные проекты, все проекты команд, где человек админ, и «Вся команда» проекты команд, где он член; пересчитывается по `project.changed`.

## 15. Тесты

Сначала миграция и тесты на настоящем Postgres, потом ручки (правила проекта).

- Тест-обход всех адресов получает виды доступа «внутри команды», «админ команды», «чтение для гостей». Адрес без пометки делает тест красным.
- Негативные тесты на каждый вид данных для **постороннего**, **гостя** и **члена команды, которого нет в списке проекта**: проект, вики, файлы, папки, поиск, список людей, лента, события WebSocket, e-mail.
- Видимость: «Только участники» не пускает члена команды, но пускает администратора команды; «Вся команда» пускает членов; гость не получает других проектов; смена режима даёт и убирает доступ сразу, в REST и в WebSocket; выход из команды отзывает неявный доступ и явные участия.
- Гость и вики: при выключенной настройке нет ничего (ни страниц, ни файлов, ни событий, ни поиска); при включённой читает и скачивает, любая запись даёт отказ.
- Администратор команды: видит все проекты, роль «администратор», в окне «Участники» помечен, «убрать» не работает.
- Сценарий из примера в разделе 1 как e2e: Лена, Артём, Игорь.
- «Личное»: создаётся с аккаунтом (в том числе через CLI), нельзя архивировать, владелец не может выйти, быть убранным или понижен, не считается в лимит.
- Проверка по всей базе: у каждого проекта есть команда, у каждого аккаунта ровно одна личная команда, у каждой команды есть админ.
- Миграция вверх и вниз.

Независимой внешней проверки безопасности это не заменяет (раздел 16).

## 18. Не входит

- Проект в нескольких командах; вложенные команды; удаление и передача команды.
- Права на отдельные страницы вики; публичные ссылки.
- Перенос проектов между командами (отложено).
- «Секретные» проекты, скрытые от администраторов команды.
- Квоты на файлы.
- Роли, кроме двух в команде и двух в проекте.
- Регистрация, почта, «Забыли пароль?»: отдельные этапы после К3.

Независимой внешней проверки безопасности у нас нет: мои тесты проверяют только то, что придумал я. Перед тем как пускать людей, которые друг другу не доверяют, нужна внешняя проверка.
