# PlexoLab

Десктоп-приложение для небольшой команды разработки: канбан-доска, бэклог, модули, релизы и вехи, вики с файлами, документы (страница и холст), активность, ссылки команды. Клиент на Tauri 2 + React, бэкенд на Rust (axum) и PostgreSQL. Интерфейс повторяет макет из `design/`.

Правила проекта: `CLAUDE.md`. Этапы работы: `docs/PLAN.md`. Сейчас готовы этапы 0 (каркас), 1 (дизайн-система, AppShell и Sidebar), 2 (бэкенд: миграции, вход, сид), 3.1 (бэкенд доски: проекты, колонки, задачи, перенос, подзадачи, комментарии, метки), 3.2 (клиент доски), 4 (бэклог, модули, вехи, релизы), 5 (вики, редактор, файлы), 6 (документы и холст), 7 (активность и ссылки команды) и 8 (обновления в реальном времени).

## Требования

- Rust stable (MSVC-тулчейн на Windows) и Visual Studio Build Tools с компонентом C++.
- Node.js 24 и npm.
- WebView2 (в Windows 11 уже есть).
- PostgreSQL 18 нужен бэкенду и его тестам (на этой машине стоит локально, база `plexolab`, пароль `postgres` — `dev`, только для разработки).

## Команды

Запускать из корня репозитория:

| Команда | Что делает |
|---|---|
| `npm run dev-server` | запускает сервер (применяет миграции, слушает `127.0.0.1:8080`), настройки из `.env` |
| `npm run seed` | заполняет пустую базу демо-данными. Параметры: `npm run seed -- --reset` (сначала стереть всё), `--today 2026-10-18`, `--password dev` |
| `npm run dev-app` | запускает клиент в окне Tauri (первая сборка занимает несколько минут) |
| `npm run dev-app-web` | клиент в обычном браузере на `http://localhost:1420`, без Tauri. Витрина компонентов: `/showcase` (обе темы) или `/showcase?theme=dark` |
| `npm run test` | тесты сервера (нужен Postgres), линтер, проверка типов и сборка клиента |
| `npm run test-visual` | Playwright: сравнение с эталоном и снимки витрины (нужен браузер, см. ниже) |
| `npm run update-visual` | пересоздать снимки витрины после намеренных изменений вида |
| `npm run build-server` | релизная сборка сервера |
| `npm run build-app` | установщик NSIS (настройки упаковки появятся на этапе 9) |

Проверка сервера: `GET http://127.0.0.1:8080/healthz` отвечает `ok`.

Перед первым запуском клиента: `npm --prefix app install`.

## Сервер

**Настройки.** Скопируйте `.env.example` в `.env` (файл в git не попадает). Сервер читает переменные окружения, `.env` подхватывается автоматически при разработке.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | подключение к PostgreSQL (обязательно) |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов (обязательно) |
| `BIND_ADDR` | адрес сервера, по умолчанию `127.0.0.1:8080` |
| `DATA_DIR` | папка данных, по умолчанию `./data`; загруженные файлы лежат в `DATA_DIR/files/<uuid>` |
| `MAX_UPLOAD_MB` | самый большой загружаемый файл в мегабайтах, по умолчанию 25 (от 1 до 2048) |
| `CORS_ORIGINS` | откуда клиенту можно ходить в API, через запятую. По умолчанию адреса Tauri (`http://tauri.localhost` и др.) и Vite (`http://localhost:1420`) |
| `EXPOSE_OPENAPI` | `true`: отдавать схему API по `/api/v1/openapi.json`. По умолчанию выключено (в боевом режиме схема никому не нужна), в `.env` для разработки включено |
| `RUST_LOG` | уровень логов, по умолчанию `info`; в логе каждый запрос с временем ответа |

**Пользователи.** Публичной регистрации нет, пользователей создаёт администратор из командной строки. Пароль лучше передавать через стандартный ввод, чтобы он не попал в историю команд:

```powershell
'длинный-пароль' | cargo run --manifest-path server/Cargo.toml -- user add --email lena@example.com --name "Лена М." --role Frontend --admin --password-stdin
```

На сервере то же самое готовым бинарником: `server user add ...`. Через `npm run` команду с паролем из пайпа не запускайте: в PowerShell пайп заставляет запускаться `npm.ps1`, и он теряет аргументы.

Параметры: `--email`, `--name` (обязательно), `--role`, `--tone 0..4` (цвет аватара), `--admin`, `--password` или `--password-stdin` (не короче 8 символов). Миграции на пустой базе применяются сами.

**Смена пароля** (если сотрудник забыл или пароль скомпрометирован):

```powershell
'новый-длинный-пароль' | cargo run --manifest-path server/Cargo.toml -- user passwd --email lena@example.com --password-stdin
```

На сервере: `server user passwd ...`. Команда меняет пароль и сразу завершает все сессии этого человека, на каждом устройстве ему придётся войти заново. Токен доступа, уже выданный ранее, действует до конца своих 12 часов. Windows PowerShell 5.1 при передаче пароля через пайп добавляет в начало невидимый маркер, команды его вырезают сами.

**Демо-данные.** `npm run seed` заполняет пустую базу данными из `seed()` макета: 5 пользователей (пароль `dev`, вход `lena@example.com`), 3 проекта, 24 задачи, модули, вехи, релизы, вики, документы, файлы (записи без файлов на диске), ссылки и активность. Даты сдвигаются так, чтобы «сегодня» было реальной датой, а события ленты («12 минут назад», «вчера, 18:20») отсчитываются от настоящего момента. С `--today 2026-10-18` «сегодня» — этот день, а «сейчас» — его полдень по UTC: так лента получается одной и той же в любой день (нужно тестам). Если пользователи уже есть, сид ничего не делает. В ленте сида вместо «PR #312 влит в main» из макета стоит «WEB-137 … добавлен PR #315»: приложение не умеет отмечать «влит в main», единственное событие кода, которое оно пишет, — «добавлен PR», когда в задаче заполнили поле PR. `--reset` стирает все данные, поэтому его нужно запускать только на базе разработки.

**API.** Все ручки под `/api/v1`, проверка живости: `GET /healthz`. Схема OpenAPI: `server openapi --out файл.json` (сервер и база не нужны, так клиент получает типы), а при `EXPOSE_OPENAPI=true` ещё и `GET /api/v1/openapi.json`. Ошибки всегда в виде `{ "code": "...", "message": "..." }`.

| Ручка | Что делает |

| `POST /api/v1/auth/login` | вход по e-mail и паролю: токен доступа (JWT, 12 часов) и refresh-токен (30 дней) |
| `POST /api/v1/auth/refresh` | обмен refresh-токена на новую пару, старый перестаёт действовать |
| `POST /api/v1/auth/logout` | завершить сессию (удалить refresh-токен) |
| `POST /api/v1/auth/password` | смена пароля (нужен токен): проверка текущего (неверный это 400 `wrong_password`, а не 401, иначе клиент счёл бы сессию потерянной), новый от 8 символов; все прежние сессии завершаются (refresh-токены удаляются, а выданные раньше токены доступа живут до конца срока, до 12 часов), этому устройству сразу выдаётся новая пара токенов |
| `GET /api/v1/me`, `GET /api/v1/users` | текущий пользователь, участники команды в порядке добавления (нужен токен, без него 401) |

Токен доступа передаётся в заголовке `Authorization: Bearer ...`. В базе лежит только sha256 refresh-токена.

**Лента активности и ссылки команды.** Записи в ленту делает сервер сам, в той же транзакции, что и действие (перенос, создание, комментарий, релиз, вики, документ, файл, модуль); клиент ленту только читает. `GET /activity` отдаёт `{ items, next }`: до 50 событий от новых к старым, в `next` курсор для следующей страницы (`before=`), `null` на последней; когда событий ровно 50, курсора нет. Курсор — время события в микросекундах и его идентификатор, поэтому события с одинаковым временем не теряются и не повторяются, а новое событие, появившееся пока читают, не сдвигает страницы. В каждом событии `category`: `tasks` (перенос, создание, удаление задачи), `comment`, `code`, `doc` (документы проекта), `wiki` (страницы вики), `release`, `file`, `module`; по ней же работает фильтр `kind`. Незнакомая категория, испорченный курсор или `actor` не в виде uuid дают 400. Группы ссылок идут в порядке создания, ссылки в группе в порядке добавления. Адрес сервер приводит к `http(s)://`: без схемы получает `https://`, пустой адрес, адрес из одной схемы и адрес с переносами строк отклоняются (400), чужая схема (`javascript:`, `ftp://`) схемой не считается и становится частью адреса после `https://`. Ссылки и группы в ленту не пишутся (в макете этих действий там нет). Правка самой ссылки (`PATCH /links/{id}`) не сделана: в макете ссылку нельзя править, только добавить и удалить.

**Проекты, участники и доступ (этап П2, `docs/PROJECTS.md`).** У проекта есть участники с ролью администратора или участника, глобальный админ (`users.is_admin`) видит и правит все проекты. Создать проект может любой, в проект зовут по e-mail существующего аккаунта, приглашённый принимает или отклоняет приглашение; проект архивируется, не удаляется; единственный администратор не может выйти, понизить себя или быть убранным. Метки у каждого проекта свои. Ручки получают проект только через `api::access` (`server/crates/api/src/access.rs`): чужого проекта «нет» (404), администраторское действие участнику недоступно (403). Доказательство, что ни одна ручка не забыта: тест `server/crates/api/tests/access.rs` берёт все адреса из схемы OpenAPI, требует у каждого пометку доступа и вызывает адреса проекта от имени постороннего (404), участника (403 на администраторское) и администратора; новый адрес без пометки роняет тест, а убранная проверка в обработчике ловится (проверено вручную). События WebSocket получают только участники проекта (`events::Audience`), лента отдаёт события моих проектов и общие, вложения задач скачивают только участники. Вики и библиотека файлов общие для всех вошедших (`access::wiki`), документы, ссылки и лента принадлежат проекту (этап П5, ниже). Миграция `0013` сделала всех нынешних пользователей участниками всех проектов, обратная лежит в `server/migrations_down` и проверяется тестами (`crates/db/tests/members.rs`). Интерфейс этих возможностей описан ниже (этап П3).

**Проекты в интерфейсе (этап П3, `app/src/features/projects/`).** «+» у заголовка «Проекты» открывает окно «Новый проект» (название, цвет, ключ); он прозрачен, пока на заголовок не навели курсор или не встал фокус, поэтому боковое меню в покое совпадает с эталоном. Правая кнопка на проекте открывает меню: «Настройки проекта» (только администратору) и «Выйти из проекта» (вторым нажатием; единственному администратору сервер отвечает 409, текст показывается плашкой). Окно «Настройки проекта» с вкладками «Основное», «Участники», «Метки», «Архив» собрано из деталей окна «Настройки»; «Приглашения» и «Архив проектов» лежат в меню пользователя, у «Приглашений» счётчик неотвеченных и точка рядом с именем внизу бокового меню. Окна ходят в API обычными запросами (`features/projects/api.ts`), а не через `useMutation`: им нужен текст ошибки сервера на месте («Аккаунта с таким адресом нет»), а не общая плашка; свои события сервер клиенту не шлёт, поэтому после действия кэш перечитывается там же. События `project.changed` и `invite.changed` обновляют проекты, доску, участников и приглашения у остальных клиентов, убранный из проекта теряет его без перезагрузки. Исполнителем задачи можно назначить только участника проекта. Если проектов нет вообще, на страницах проекта показывается «У вас пока нет проектов» с кнопкой «Создать проект». Автотесты: `tests/visual/projects.spec.ts` (два браузера в одном тесте, снимки окон в обеих темах свои, эталона в макете у них нет).

**Ключи задач (этап П4, `docs/PROJECTS.md`, раздел 4).** У модуля может быть ключ (`SEO`), у проекта тоже; подпись id задачи собирается при показе: ключ модуля, если задача в его ряду, иначе ключ проекта, иначе `TASK`. Поле «ключ» лежит в карточке модуля («Модули»), ключ проекта в «Настройках проекта». Первый ключ у модуля и его снятие переносят задачи в другой ряд (новые номера в порядке старых), перенос задачи между рядами тоже даёт новый номер, прежние id пишутся в таблицу `task_old_ids`; переименование меняет только подпись. Перед такой сменой клиент спрашивает «У N задач изменятся id. Продолжить?». Номера удалённых задач не возвращаются, нумерация вернувшегося ключа продолжается, а не повторяется. Ключи внутри проекта не повторяются (занят и `TASK`, пока у проекта нет ключа), в разных проектах могут. Сортировка по ID в таблице идёт по ключу и номеру. Проверки: `server/crates/api/tests/keys.rs` (в том числе параллельные запросы и правило по всей базе) и `tests/visual/keys.spec.ts`.

**Документы, ссылки и лента по проектам (этап П5, `docs/PROJECTS.md`, раздел 2).** Документы (страница и холст) и группы ссылок принадлежат проекту: у каждого проекта свои списки и свой порядок документов, миграция `0014` отнесла существующие к первому проекту (обратная лежит в `server/migrations_down`, проверена тестами `crates/db/tests/project_docs.rs`). Список и создание идут по проекту (`/projects/{id}/docs`, `/projects/{id}/link-groups`), остальные адреса по самой записи: проект находится по ней, и человек должен быть его участником, иначе 404 (в тест-обходе `access.rs` все эти адреса помечены). Лента проекта (`/projects/{id}/activity`) показывает события проекта и общие события без проекта (вики, файлы библиотеки). События документов и ссылок получают только участники проекта. Вложения задач в библиотеку файлов не входят и скачиваются только участниками проекта задачи. На экране «Документы», «Ссылки команды» и «Активность» стали страницами выбранного проекта (тексты заголовков остались как в макете), открытый документ из другого проекта закрывается. Фильтр «Исполнитель» на доске предлагает участников проекта и тех, у кого в проекте есть задачи: вышедший остаётся, пока на нём есть задачи, а тот, у кого нет ни членства, ни задач, не показывается. Так же устроен фильтр «Участник» в ленте (участники проекта и все, у кого есть собственные события проекта; авторы общих событий вики в список не входят; список отдаёт `GET /api/v1/projects/{id}/activity/actors`). «Ответственный» в карточке модуля выбирается из раскрывающегося списка участников проекта, сервер другого не принимает. Проверки: `server/crates/api/tests/project_data.rs`, `tests/visual/project-data.spec.ts`.

**Живые обновления (WebSocket).** Клиент подключается к `/api/v1/ws`, первым сообщением присылает токен доступа (не в адресе: адреса попадают в журналы), получает `ready` и дальше события об изменениях других участников. Протокол, коды закрытия (4401 токен не принят или истёк, 4408 не дождались входа или ответа на `ping`, 1001 сервер останавливается) и список событий описаны в `docs/DATA-MODEL.md` и в начале `server/crates/api/src/ws.rs`. События рассылает не каждая ручка по отдельности, а один слой над всеми ручками (`events::publish_events`): он видит ответ уже после `commit` и рассылает события только на успешный ответ. Какие события даёт ручка, записано в таблице `events::TABLE`; тест сверяет её со схемой OpenAPI (новая ручка записи без строки в таблице не пройдёт `cargo test`) и с ручками в обратную сторону (нет ли устаревших строк). Событие не несёт данных, только «что поменялось» (`id` записи и `project_id`, если ручка их знает), и метку клиента `origin` из заголовка `X-Client-Id`. Перенос карточки идёт тем же `PATCH /tasks/{id}`, что и правка, а тело запроса слой не разбирает, поэтому он даёт `task.updated`. Лишние события безвредны (клиент просто перечитает), потерянные нет, поэтому таблица щедрая: например, ручки, которые обычно пишут в ленту, всегда дают и `activity.created`. Внутри процесса события идут по каналу `tokio::sync::broadcast` на 256 событий; кто отстал, получает `resync` и перечитывает всё. Соединений не больше 100 (дальше 503), на каждое одна задача tokio. При остановке сервера по Ctrl+C соединения закрываются сами (`AppState::begin_shutdown`).

**Бэклог, модули, вехи.** Отдельного списка бэклога нет: это задачи с `column_id = null` из ответа `GET /projects/{id}/board`, порядок и «На доску» делает тот же `PATCH /tasks/{id}`. Модули и вехи приходят в том же ответе, вместе с `tasks_total` и `tasks_done`: прогресс считает сервер (задача готова, если лежит в колонке с отметкой «Готово»; задачи из бэклога входят в «всего», но не в «готово»). Поэтому прогресс сам пересчитывается при смене колонки задачи.

**Лента активности** получает записи от модулей (категория `module`: создан, удалён, «переведён в «В работе»»), вех и релизов (категория `release`: создан, удалён, смена статуса, «отмечен шаг «…»»; шаг пишется только когда его отмечают, а не снимают). Переименования, даты и заметки в ленту не попадают.

**Вики и версии.** У страницы есть номер версии `rev`: он растёт на единицу при каждом изменении названия или текста. `PATCH /wiki/{id}` с названием или текстом требует `rev`, который клиент видел последним. Если страницу успели изменить, ответ 409 вида `{ "code": "conflict", "message": "...", "current": { ...страница... } }` и ничего не записывается; клиент показывает баннер и либо берёт `current`, либо повторяет свой текст с новой версией. Сохранение того же содержимого версию не поднимает. В ленту (`doc`) пишутся только создание и удаление страницы, правки текста нет. **Перенос** (`parent_id`: новый родитель, `null` — корень; `before_id`: перед какой страницей встать среди страниц этого родителя, `null` — в конец; только `before_id` меняет порядок у прежнего родителя) `rev` не требует и не меняет: это место в дереве, а не содержимое, поэтому перенос открытой страницы не даёт конфликта с её собственным сохранением. Переносить страницу внутрь неё самой или её вложенных нельзя, `before_id` должен быть страницей этого родителя. Если страница уже стоит на этом месте, ничего не пишется.

**Документы и холст.** Название и текст документа живут под версией `rev`, как у страниц вики: `PATCH /docs/{id}` с названием или текстом требует `rev`, при расхождении ответ 409 с актуальным документом в `current`, сохранение того же содержимого версию не поднимает. **Режим** («Страница» или «Холст») и **перенос** (`before_id`: перед каким документом встать, `null` — в конец) `rev` не требуют и не меняют: это вид и место в списке, поэтому переключение режима при открытом редакторе не даёт конфликта. Список общий для команды: новые документы встают первыми, порядок меняют перетаскиванием карточек, позиции дробные (как у задач). **Звёздочка** у каждого участника своя (`starred` в ответе считается для того, кто спрашивает; `?starred=true` отбирает его избранные). Поиск `?q=` идёт по названию и тексту без учёта регистра (см. «Что нужно знать заранее» про локаль базы). В списке текста нет: приходят фрагмент (три первые строки без разметки через « · ») и, у документов в режиме «Холст», объекты для миниатюры. **Холст** сохраняется целиком: `PUT /docs/{id}/canvas` с карточкой текста, полным списком объектов и стрелок. Объекты, которых нет в списке, удаляются со своими стрелками, остальные обновляются на месте (слой не меняется), новые ложатся сверху; идентификаторы выдаёт клиент. Проверка (тип, цвет 0–7, числа в пределах, не больше 500 объектов и 2000 стрелок, стрелка соединяет два разных объекта один раз) идёт до записи, любая ошибка оставляет холст прежним. Холст без `rev`: последнее сохранение побеждает; у холста своя версия `canvas_rev`, которая растёт при каждом сохранении, чтобы клиент отличал свежее состояние от запоздавшего ответа. Время правки документа обновляется при правке названия, текста и холста. В ленту (`doc`) пишутся создание («создан» или «создан как холст») и удаление.

**Файлы.** Содержимое пишется на диск потоком, файл целиком в память не читается. Лимит одного файла задаёт `MAX_UPLOAD_MB` (больше: 413), за один запрос не больше 50 файлов. Если запись в базу не удалась, записанное на диск убирается. Файл, прикреплённый к странице без указания папки, попадает в папку «Вложения» (создаётся при первой загрузке). Удаление страницы вики файлы не трогает, они остаются в библиотеке без страницы; удаление задачи убирает её вложения и с диска. У записей из сида содержимого нет, скачивание такого файла отвечает 404. В ленту (`file`) пишутся загрузка и удаление файлов.

**Перенос карточки** делается одним `PATCH /api/v1/tasks/{id}`:

| Тело | Что произойдёт |
|---|---|
| `{ "column_id": "<колонка>" }` | в конец этой колонки |
| `{ "column_id": "<колонка>", "before_id": "<задача>" }` | в эту колонку перед указанной задачей (она должна лежать в этой колонке) |
| `{ "before_id": "<задача>" }` | в своей колонке перед указанной |
| `{ "column_id": "<своя колонка>", "before_id": null }` | в конец своей колонки |
| `{ "column_id": null }` | в бэклог (так же, `before_id` работает внутри бэклога) |

Остальные поля можно слать в том же запросе: что не передано, не меняется, а `null` очищает необязательные поля (исполнитель, даты, модуль, веха). Позиции дробные: между соседями берётся среднее, а когда зазор меньше 1e-6, позиции всей колонки пересчитываются с шагом 1024. Все изменения доски идут по очереди внутри проекта, в ленту активности пишутся создание, удаление, перенос между колонками, комментарий и добавление PR, в той же транзакции.

**Уведомления и упоминания (этап Н3, `docs/OFFLINE-NOTIFY-SEARCH.md`, раздел 2).** Два повода: человека назначили исполнителем (`PATCH /tasks/{id}`, себя назначить не сообщается, повторное непрочитанное по той же задаче заменяется свежим) и упомянули в комментарии (`POST /tasks/{id}/comments`). Упоминание в тексте метка `@[id человека]` (`domain::mentions`), а не имя, поэтому после смены имени старые комментарии показывают новое; сервер проверяет метки: только участники проекта, не больше 20, иначе 400, и сохраняет список в `comments.mentions`. Уведомления в таблице `notifications` (миграция `0017`, обратная в `server/migrations_down`, проверена тестами `crates/db/tests/notifications.rs`): `GET /notifications` (новые первыми, до 100, и число непрочитанных), `POST /notifications/{id}/read` и `POST /notifications/read-all`. Видны только уведомления проектов, где человек участник и которые не в архиве. Старое сервер чистит при создании нового (прочитанное старше 30 дней и всё сверх 200 самых новых у человека), фонового процесса нет. Адресату уходит событие `notification.changed` лично ему (`Audience::Users`), в том числе в другие его окна при прочтении. В тест-обходе `access.rs` для чужой записи появился вид доступа `Own`: чужое уведомление «не найдено» всем, даже администратору проекта. Тесты: `crates/api/tests/notifications.rs` (22), `crates/db/tests/notifications.rs` (21), модульные `domain::mentions` и `routes/notifications.rs`.

**Поиск по названиям (этап Н4, `docs/OFFLINE-NOTIFY-SEARCH.md`, раздел 3).** `GET /api/v1/search?q=` ищет по названиям задач (и их id, `WEB-141`), документов, страниц вики и файлов библиотеки, по восемь лучших каждого вида. Без расширений Postgres и без индексов: подстрока без учёта регистра через `lower()` и `position` (так `%`, `_` и `\` в запросе обычные знаки), содержимое не ищется. Задачи и документы только из проектов человека (глобальный администратор видит все), без архивных; вики и файлы библиотеки общие. Порядок: точное совпадение с id, начало названия или id, остальное, внутри группы недавнее выше. Запрос длиннее 100 символов отклоняется (400), пустой даёт пустые списки. Важна локаль базы (см. «Локаль базы данных» ниже): при старте сервер проверяет `lower()` и пишет предупреждение в журнал, если база не различает регистр русских букв. Тесты: `crates/api/tests/search.rs` (22), `crates/domain/src/search.rs`.

**Команды: схема и права (этап К1, `docs/TEAMS.md`).** Над проектами появился уровень «Команда». Вики, папки и файлы библиотеки принадлежат команде (адреса `/api/v1/teams/{id}/wiki`, `/files`, `/folders`; страница, папка и файл находятся по своему id, команда берётся из записи), у проекта есть команда и видимость («Только участники» или «Вся команда»). Проект видит явный участник, администратор его команды (он же администратор проекта, убрать его из проекта нельзя; блокировки «единственный администратор проекта» больше нет) и, при «Вся команда», любой член команды; администратор сервера видит всё. Вики и библиотеку читает член команды и гость проекта (явный участник, не член) при включённой настройке команды `guests_read_wiki`, пишет только член команды: гость получает 403, посторонний 404. У каждого аккаунта с рождения есть личная команда «Личное»: её создаёт триггер базы в той же операции, что и аккаунт (`server user add`, сид, будущая регистрация). Миграция `0018` отнесла существующие вики, файлы, проекты и аккаунты к общей команде «Dream Team» (обратная: `server/migrations_down/0018_teams.down.sql`; **перед боевой миграцией нужна копия базы**, доступа к серверу у меня нет). Правила доступа записаны один раз в функциях базы `can_access_project`, `is_project_person`, `can_read_team`, а в коде все ручки получают проект и команду через `api::access`. События вики и файлов идут только тем, кто читает вики команды (`Audience::Team`, в событии `team_id`), метки «кто в каком блоке» на странице вики тоже; лента проекта подмешивает события вики своей команды, поиск (`GET /search?team=&q=`) идёт по одной команде. `GET /users` отдаёт только людей, которых человек видит (он сам, члены его команд, участники доступных проектов и те, чьи имена остались на видимых данных), чужие e-mail скрыты по правилам раздела 8. Пока в клиенте нет переключателя команд (этап К3): вики, файлы и поиск идут по команде открытого проекта, а если вики её не читать, по первой команде с доступной вики («Личное»). Проверки: `server/crates/api/tests/teams.rs`, `access.rs` (обход всех адресов, вики команды и гость), `server/crates/db/tests/teams.rs` (миграция вверх и вниз, правила в базе), `realtime.rs`.

**Миграции** лежат в `server/migrations` и являются источником правды о схеме. От `docs/DATA-MODEL.md` они отличаются только защитой и индексами: проверки значений (`tone`, `color`, `kind`, e-mail в нижнем регистре), уникальность метки без учёта регистра, индексы по внешним ключам, колонка `created_at` у refresh-токенов и колонка `seq` у проектов, меток, участников, модулей и папок (порядок создания: так идут проекты в боковом меню, метки в панели задачи, исполнители в фильтрах, модули на своём экране и папки в библиотеке, как в макете, а не по алфавиту). Если базу заполняли сидом до миграций `0007`–`0010`, выполните `npm run seed -- --reset`, чтобы порядок совпал с макетом.

**Тесты сервера** (`npm run test-server`) идут на настоящем Postgres: каждый тест получает временную базу `_sqlx_test_*`, которая удаляется после него. Нужен `DATABASE_URL` с пользователем, который может создавать базы.

### Визуальные тесты

- **Оптимистичные обновления.** Перенос, правка полей, смена колонки, подзадачи и удаление показываются на экране сразу. Если сервер отказал, экран возвращается к прежнему состоянию. Когда на сервере не остаётся ожидающих изменений, доска перечитывается и берёт точные позиции. Создание (задача, колонка, комментарий, метка) ждёт ответа сервера, потому что номер `WEB-N` выдаёт он.
- **Перетаскивание.** `@dnd-kit/core` отвечает за захват указателя и копию под ним, а место заглушки определяется по элементу под указателем, как в макете: над карточкой выше или ниже середины, над колонкой в конец, над днём календаря. Положение указателя берётся из событий указателя (`lib/usePointer.ts`), а не как «точка нажатия + delta» из dnd-kit: delta включает прокрутку контейнеров, и пока доска прокручивается сама у края окна, цель уезжала бы от указателя на величину прокрутки (проверяет `board-drag.spec.ts`, «автопрокрутка доски при переносе»). Бросок не над целью ничего не меняет, бросок на то же место запроса не отправляет. Клавиатурного переноса, как и в макете, нет: статус и колонку можно сменить в панели задачи.
- **Что хранится на компьютере** (не уходит на сервер): тема, страница, проект, вид, фильтры и «Отображение». Поиск, открытая задача и месяц календаря не сохраняются.

- **Редактор.** Текст страницы — одна строка markdown, блок — диапазон строк. Нажатие на блок делает его активным (`mousedown` с `preventDefault`, поэтому фокус не мигает), остальные блоки отрисованы. Потеря фокуса и Esc завершают правку и чистят текст: пустые маркеры (`-`, `#`, `>`) удаляются, лишние пустые строки схлопываются. «Защита токеном»: блок помнит номер своей активации, и запоздавший blur старого блока ничего не завершает. Кнопки панели не забирают фокус у поля. Внешние ссылки открываются через `tauri-plugin-opener` (в браузере — новая вкладка), открываются только `http` и `https`.
- **Сохранение.** Черновик страницы живёт вне компонента: если уйти со страницы, не дождавшись, сохранение всё равно закончится, а вернувшись, человек увидит свой текст. Правка уходит на сервер через 600 мс после последнего нажатия, при выходе из правки и при уходе со страницы. Отправляется только изменённое (текст или название) и версия `rev`, которую клиент видел. Правки во время отправки уходят следующим запросом с новой версией. Сервер не ответил: плашка «Не удалось сохранить страницу, попробуем ещё раз», текст остаётся на экране, повтор через 5 секунд.
- **Слияние правок при конфликте** (`lib/merge.ts`, `PageDraft.merge`). Ответ 409 не сразу показывает баннер: три версии у клиента уже есть (то, что я видел последним, мой текст, чужой из `current`), и он сливает их по строкам, как git (diff3). Правки в разных местах склеиваются, сохраняются поверх чужой версии, слияние тихое, без сообщений (сообщение «Объединено с правками» было, но показывалось только тому, чьи правки слились, и выглядело странно, его убрали). Сервер и протокол не менялись: слияние целиком на клиенте. Правила: как git, правки считаются пересекающимися, если задевают одни и те же строки или стоят вплотную (соседние строки списка), тогда прежний баннер. Два отличия от git. Первое: вставку или удаление блока можно сдвинуть через равные строки (пустую строку между абзацами), иначе вставка между абзацами давала бы ложный конфликт с правкой любого соседа. Второе: две разные вставки в одно место (оба дописали новый блок в конец, оба вставили между абзацами) не конфликтуют, остаются обе: чужая, уже сохранённая, выше, моя ниже (`sameSpot`); в git это конфликт, но двоим, начавшим писать с новой строки одновременно, баннер только мешал. При сравнении строк пустые строки весят меньше абзацев (`TEXT_WEIGHT`), иначе добавленный рядом абзац мог перетянуть совпадение у соседнего. Одинаковые правки с обеих сторон принимаются один раз. Правка, убравшая или добавившая одно ограждение ```, рядом с чужой правкой не склеивается (блок кода «поплыл» бы). Название сливается отдельно: поменял один, значит берётся его значение, оба по-разному — баннер. Не больше трёх слияний подряд (сосед мог сохраниться снова), потом баннер. Слишком большие тексты (больше 4 млн клеток сравнения) не сливаются. После слияния редактор пересоздаётся, но тот же блок открывается на новом месте, курсор остаётся: человек продолжает печатать без щелчка (`restore` в состоянии черновика, `registerProbe` у редактора; карта строк «было, стало» приходит из слияния). То же для чужой версии, пришедшей вживую, когда своих правок нет (`PageDraft.adopt`): редактор тоже пересоздаётся, но раньше блок при этом закрывался, фокус пропадал и всё, что человек печатал дальше, уходило в пустоту; теперь `trackBlock` считает, куда блок сдвинулся (вставка выше сдвигает, правка внутри растягивает или сжимает, дописанные вплотную строки входят в блок), и он открывается там же. Если сосед удалил именно этот блок, открывать нечего. Холст так не сливается: он по-прежнему сохраняется целиком, последнее сохранение побеждает.
- **Конфликт версий.** Если слить правки нельзя, ответ 409 останавливает сохранение и показывает баннер «Страницу изменил другой участник» с кнопками «Загрузить его версию» (свой текст отбрасывается) и «Оставить мою» (свой текст записывается поверх с актуальной версией; название, которое ты не трогал, остаётся чужим). Пока баннер открыт, правки не уходят. В макете баннера нет, он собран из переменных и размеров макета, как плашка об ошибке.
- **Перенос страниц по дереву** (в макете его нет, добавлен по просьбе владельца; эталонного снимка нет, заглушка собрана из классов макета). Страницу берут за строку и ведут: исходная строка приглушается (40%, как карточка), на месте падения встаёт пунктирная заглушка `.ph` нужной глубины. Строка делится по высоте на зоны: **верхняя четверть** — перед страницей, **середина** — внутрь, в конец вложенных (строка подсвечена, заглушки нет), **нижняя четверть** — после страницы. У раскрытой страницы «после» значит после всей её ветки на её уровне; в нижней четверти последней строки ветки уровень выбирает положение указателя по горизонтали: правее — последней вложенной, левее — после родителя, ещё левее — после родителя родителя (уровни, на которых строка последняя в своей ветке). Ниже последней строки (в том числе над «Новая страница») — в конец корня. Возврат на прежнее место, бросок на себя и на свои вложенные, а также пока идёт поиск, ничего не делают. Перенос показывается сразу и откатывается при отказе сервера; сервер версию страницы не трогает, поэтому перенос открытой и редактируемой страницы не мешает её сохранению. Как и у задач, клавиатурного переноса нет.
- **Ссылки `[[Страница]]`** открывают страницу без учёта регистра, а если страницы нет, она создаётся и открывается с курсором. Ссылка на несуществующую страницу нарисована серой с пунктиром.
- **Файлы.** Вся библиотека загружается одним запросом, а поиск, тип и папка отбираются на экране (так они откликаются мгновенно); серверные фильтры `GET /files?folder=&kind=&q=` тоже работают и покрыты тестами. Название файла нажимается и скачивает его (в макете скачивания нет, но этап требует: выглядит название как раньше). Новые файлы идут первыми (в макете новые добавлялись в конец списка). Вложения задач (панель задачи) загружаются и скачиваются так же; в библиотеку вики они не попадают.
- **Что хранится на компьютере:** к списку добавлена последняя открытая страница вики; при входе дерево раскрыто до неё.

- **Страница и холст** — один и тот же `div.cv` с разными классами, поэтому при переключении режима редактор текста не пересоздаётся: активный блок и введённое остаются. Объекты холста рисуются только в режиме «Холст», текст и название общие.
- **Холст — камера** (`styles/canvas.css`, `features/docs/camera.ts`, `useCanvasView.ts`, по просьбе владельца; в макете это была область с полосами прокрутки). Размер прокрутки считался по самому дальнему объекту и менялся под рукой: блок, которого тянули назад, «не шёл» за мышью (браузер сам урезал прокрутку), у края окна холст не прокручивался, а влево и вверх объекты не уходили. Теперь окно холста обрезает по краям (`overflow: clip`), внутри слой `.cv-world`, который сдвигается `translate` и масштабируется `scale`; положение объектов остаётся в координатах холста (`left`/`top` как раньше, на 100% и в начальной позиции холст выглядит как в макете). Холст двигают колесом (с Shift по горизонтали, тачпад по обеим осям), пустым местом и средней кнопкой; колесо над блоком карточки со своей прокруткой (широкий код, таблица) по его оси принадлежит блоку целиком: главная ось жеста определяется с учётом Shift, и если по ней блок прокручивается, браузер крутит его сам, а холст стоит, в том числе когда блок дошёл до края (остаток жеста, у тачпада это инерция, холст не уносит; `overscroll-behavior: contain` в `canvas.css` не пускает его дальше на страницу и на «назад» по жесту). Вертикальное колесо над блоком, который прокручивается только вбок, двигает холст. Положение объекта при переносе считается в координатах холста по последнему положению указателя, поэтому не зависит от того, куда за это время сдвинулась камера; у края окна (48 px) холст едет сам, объект остаётся под указателем. Координаты от −100 000 до 100 000 (сервер принимает отрицательные, `MAX_COORD` в `domain/docs.rs`), миниатюра в списке документов сдвигается по границам содержимого. Новый объект встаёт справа от карточки, а если там не видно, в центр видимой части. С клавиатуры Tab к объекту вне окна сдвигает холст к нему. Проверяет `docs-canvas.spec.ts` («камера холста»).
  **Масштаб.** Ctrl + колесо (так же приходит щипок на тачпаде) меняет масштаб вокруг указателя, от 25% до 200%; кнопки «−», «100%» (показывает нынешний, по нажатию возвращает 100%) и «+» идут по ступеням 25, 33, 50, 67, 75, 100, 125, 150, 200, «Показать всё» ставит всё содержимое целиком в окно (не крупнее 100%). Кнопки лежат в правом верхнем углу холста (`.cv-zoom`, вне макета, оформление как у панели `.eg-tools`). Вид (сдвиг и масштаб) запоминается для каждого документа на этом компьютере (`canvasViews` в настройках, `features/docs/views.ts`; не больше 100 документов; на сервер не уходит, у других участников не меняется); если запомненный вид ничего не показывает (содержимое убрали или сдвинули), холст открывается с начала. Обработчик колеса свой, не из React: `onWheel` у React пассивный, и `preventDefault` в нём не работает. Масштаб окна приложения целиком выключен: `zoomHotkeysEnabled: false` в `src-tauri/tauri.conf.json` (на Windows это `IsZoomControlEnabled` у WebView2; поведение собранного приложения на колесе с Ctrl проверить при сборке) и `lib/noPageZoom.ts` для режима разработки в браузере и для тестов. Проверяет `docs-canvas.spec.ts` («масштаб холста»).
- **Холст.** Объект двигается за `pointerdown` с захватом указателя (`setPointerCapture`), карточка с текстом за верхнюю полоску `.note-grip`. Пока тащат, меняется только локальное состояние (`CanvasDraft.change` с `save: false`), на сервер холст уходит целиком по `pointerup`. Правки не от указателя (текст и цвет объекта, новый объект, стрелка) сохраняются через 600 мс или при уходе из документа. Пока идёт отправка, новые правки ждут и уходят следующим запросом; при сбое плашка и повтор через 5 секунд. Версия `canvas_rev` защищает холст: ответ сервера, который запоздал или пришёл от чужого сохранения, принимается только если он новее известного и своих несохранённых правок нет. Стрелка — повёрнутый `div` от границы одного объекта до границы другого; у пересекающихся объектов её нет. Клавиатурой объект можно выбрать (Enter на кнопке) и соединить стрелкой, перетаскивание, как в макете, только указателем.
- **Название и текст** сохраняются тем же `PageDraft`, что у страниц вики: пауза 600 мс, очередь, 409 и баннер «Документ изменил другой участник», повтор после сбоя. Ответ на правку текста обновляет в кэше документа только название, текст и версию, но не холст.
- **Список.** Карточки `.dcard` в сетке `.dgrid`: название, миниатюра холста (у документа-холста с объектами) или фрагмент текста, автор, дата правки, режим, число объектов; звёздочка в углу. Поиск идёт на сервер через 250 мс после последней буквы (в список текст не приходит), пока ответа нет, остаётся прежний список; пустой поиск сразу показывает всё. «Избранные» отбирает на экране и помнится после перезапуска вместе с открытым документом.
- **Перенос карточек** (в макете его нет, добавлен по просьбе владельца; эталонного снимка нет, всё собрано из классов макета). Карточку берут за любое место, кроме звёздочки, исходная приглушается (40%, как у задачи), на месте падения встаёт пунктирная заглушка `.ph.ph-col` размера переносимой карточки; тот же `DragProvider` и те же правила, что у задач. Над левой половиной карточки заглушка встаёт перед ней, над правой после неё (карточки лежат сеткой), над пустым местом сетки в конец. Над самой карточкой и над её соседом справа заглушки нет: это то же место. Порядок общий для команды, меняется сразу и откатывается при отказе сервера. При поиске или «Избранных» перенос идёт по видимым карточкам, а скрытые остаются на своих местах позади: бросок «в конец видимого» ставит документ перед тем, кто шёл в полном списке за последним видимым. Как у задач, клавиатурного переноса нет. Если перенос начался раньше, чем через 50 мс после предыдущего, dnd-kit снимает защиту от «клика после переноса» (его особенность): человек так быстро не успеет, тестам нужна пауза.
- **Что хранится на компьютере:** открытый документ и фильтр «Избранные».

- **Лента.** `useActivity` — бесконечный запрос TanStack Query: страницы по 50, курсор берётся из `next`. За последней строкой следит `IntersectionObserver` с запасом 600 пикселей: когда она подходит к экрану, грузится следующая страница, никаких кнопок «Показать ещё» нет (в макете их нет). Наблюдатель создаётся заново после каждой страницы, поэтому, если новая страница не заполнила экран, подгружается ещё одна. Ленту читают заново при каждом открытии страницы (`staleTime: 0`): человек сделал что-то на доске и сразу видит это в ленте; при обновлении перечитываются все загруженные страницы по порядку. Фильтры отправляются на сервер (`actor`, `kind`), а не отбираются на экране: иначе фильтр по редкому типу показывал бы пустоту, пока не подгружены нужные страницы. Время («12 минут назад», «вчера, 18:20») и дни считаются по часам этого компьютера. Если сохранённого участника уже нет в команде, показываются все, а сохранённое значение не стирается.
- **Фильтры хранятся на компьютере** (`actWho`, `actKind`), на сервер не уходят.
- **Метка «Модуль».** Категория добавлена по решению владельца на этапе 4 (в макете шести категорий). Цвет метки — седьмой тон `TONES` (розовый), новых цветов нет; седьмая плашка фильтра называется «Модули».
- **Тексты, которых нет в макете:** «Событий пока нет» (когда фильтры не выбраны, а событий нет: макет такого не показывает; с фильтрами остаётся «Под такие фильтры событий нет»), «Загружаю ленту…», «Загружаю ссылки…», «Не удалось загрузить …» с кнопкой «Повторить» (так же, как у релизов). Подпись страницы «Ссылки команды» переписана по решению владельца: в макете она кончается словами «Адреса в макете условные», в приложении вместо них «Нажми на карточку, и ссылка откроется в браузере» (та же длина, шапка остаётся в две строки и вёрстка совпадает с эталоном).
- **Ссылки.** Название ссылки, адрес и описание нельзя править (в макете только добавить и удалить), название группы правится на месте и сохраняется по Enter или потере фокуса. Нажатие на карточку перехватывается (`preventDefault`), адрес остаётся в `href` (виден при наведении, копируется), а открывает его `openExternal`: так окно приложения никуда не переходит. Средняя кнопка и Ctrl+клик ведут туда же. Черновики плиток «Добавить ссылку» живут, пока открыта страница.
- **Не проверено вручную:** открытие ссылки в системном браузере в окне Tauri (`npm run dev-app`). В браузерном режиме и в тестах проверена новая вкладка, а то, что в окне Tauri адрес уходит плагину `opener`, проверено модульным тестом `lib/platform/opener.test.ts`.

- **Что происходит при событии.** Чужое событие превращается в список запросов (`queryKeysFor`), они помечаются устаревшими, и те, что сейчас на экране, перечитываются; остальные перечитаются, когда их откроют. Своё событие (`origin` совпал с меткой этого запуска) пропускается: экран уже показал изменение сам. Незнакомые события пропускаются.
- **Связь потеряна.** Точка красная, клиент подключается заново с нарастающей паузой; сразу после возвращения связи (и после сообщения `resync`) перечитываются все запросы, потому что часть чужих изменений прошла мимо. Первое подключение после входа ничего не перечитывает: данные только что загружены. Когда сеть вернулась (`online`) или окно снова на виду, а связи нет, клиент подключается сразу, не дожидаясь паузы. Выход из приложения закрывает соединение.
- **Точка связи** лежит поверх аватара внизу бокового меню: зелёная (связь есть), жёлтая (подключаюсь), красная (нет связи). Она `position: absolute`, ничего вокруг не сдвигает; подпись для скринридера и подсказка при наведении. В макете такой точки нет, цвета из его переменных (`--ok`, `--warn`, `--bug-fg`).
- **Чужая правка и набираемый текст.** Поля с черновиком (`useDraftField`: название и описание задачи, модуля, релиза и т. п.) не затирают то, что человек уже начал печатать: если в поле ничего не меняли, оно берёт чужое значение, если печатают, текст остаётся и сохранится по выходу из поля поверх (последняя запись побеждает, как и раньше). Страницы вики, документы и холст принимают чужую версию, только если своих несохранённых правок нет (`PageDraft.adopt`, `CanvasDraft.adopt`), иначе сработает слияние на 409, а если слить нельзя, прежний путь с баннером конфликта. Если страницу или документ удалили, пока их правили, сохранение молча прекращается (404), а не повторяется с плашкой об ошибке каждые 5 секунд.
- **В разработке** React монтирует компоненты дважды подряд, поэтому запуск соединения отложен на такт: иначе сервер видел бы два подключения при каждом входе.
- **Не проверено вручную:** работа сокета в окне Tauri (`npm run dev-app`, WebView2). В браузерном режиме (тот же Chromium) и в тестах всё проверено. Окно Tauri на Windows открывает приложение с адреса `http://tauri.localhost`, поэтому подключения `ws://` и `wss://` допустимы; если когда-нибудь включить `useHttpsScheme`, браузерный движок запретит `ws://` к серверу на http (смешанное содержимое), и тогда понадобится плагин `tauri-plugin-websocket`.

## Клиент: работа без связи

Решения владельца: `docs/OFFLINE-NOTIFY-SEARCH.md`, раздел 1.

| Файл | Что делает |
|---|---|
| `lib/link.ts` | состояние связи (`useLink`: `down`, `readOnly`), режим «только просмотр» через 3 секунды без связи, проверка связи (`/healthz`: через 1 секунду, потом каждые 4), подписка «связь вернулась», `OfflineError` (с тестами на подменённом времени) |

| `lib/useLinkWatch.ts` | события системы `offline` / `online` и возвращение окна на передний план |
| `lib/unsent.ts` | учёт черновиков с несохранённым (вики, документы, холст), `flushUnsent`, отправка накопленного при возвращении связи |
| `lib/query.ts` | `networkMode: 'always'` (без связи запросы и изменения сразу завершаются ошибкой, а не ждут сети), `failed(q)`: ошибка только если данных нет совсем, перечитывание всего при возвращении связи |
| `components/OfflineBar.tsx` | полоска сверху рабочей области (`role="status"`) |
| `styles/offline.css` | вид закрытых кнопок (как неактивные в окне «Настройки») |
| `lib/copyTitle.ts` | название страницы-копии «Название (правки Имя, дд.мм чч:мм)», обрезка под лимит сервера в 200 знаков (с тестами) |
| `lib/closeGuard.ts`, `lib/closeAsk.ts`, `lib/useCloseGuard.ts` | защита при закрытии окна с неотправленным текстом: сначала отправка две секунды, потом вопрос; `beforeunload` в браузере, `onCloseRequested` в Tauri (с тестами) |
| `features/workspace/CloseAskDialog.tsx` | окно вопроса «Есть неотправленные правки» (из `DialogFrame`) |

- **Что считается «связи нет».** Запрос не дошёл до сервера (`NetworkError`), прокси ответил 502, 503 или 504, закрылось живое соединение (WebSocket) или система сообщила `offline`. Связь вернулась, когда сервер ответил на любой запрос, на проверку `/healthz` или живое соединение дало `ready`. Настройка «Обновлять вживую» выключена: WebSocket не работает, остаются запросы и проверка `/healthz`.
- **Режим «только просмотр».** Включается, когда связи нет 3 секунды подряд (короткий сбой не мигает блокировкой), выключается сразу, как связь вернулась. Закрыто: поля (`Input`, `Textarea`, `TitleInput`, `useDraftField` отдают `readOnly`; несколько полей без этих обёрток, например название задачи и подзадачи в панели, берут `useReadOnly()` сами), кнопки записи (у `Button`, `IconButton`, `Tick`, `Opt`, `MenuItem`, `Segmented` есть пометка `write`), перенос карточек, страниц и документов (у датчика dnd-kit бесконечный порог захвата), редактор текста (блоки не открываются, «+» и панель форматирования закрыты, галочки заблокированы), холст (объекты не двигаются, инструменты закрыты), календарь и выбор человека. Читать, открывать задачи, переходить по экранам, фильтры, вид, тема и настройки приложения работают. Новая кнопка, которая что-то записывает на сервер, должна получить `write` (или `disabled={useReadOnly()}`), иначе она нажмётся, и клиент API вернёт отказ с плашкой «сейчас можно только смотреть».
- **Загруженное остаётся на экране.** Фоновое обновление без связи заканчивается ошибкой, но данные остаются; экраны показывают «Не удалось загрузить…» только когда данных нет совсем (`failed` и проверки `data === undefined`). Вход при обрыве не теряется: токен обновляется только по ответу 401. Полноэкранное «Сервер не отвечает» бывает только при запуске приложения.
- **Черновики текста.** Страницы вики, документы и холсты при обрыве не показывают плашку «Не удалось сохранить», правки остаются в черновике, повтор через 5 секунд страхует, а когда связь вернулась, всё накопленное уходит сразу (`flushUnsent`). Дальше обычный путь: 409, слияние, при настоящем столкновении баннер (а если человек уже ушёл со страницы, копия рядом, см. ниже). Если в полоске есть неотправленное, в ней об этом сказано.
- **Копия рядом (этап Н2).** Если правки не слились с чужими (одни и те же строки), а человека нет на странице или в документе (экран закрыт дольше полусекунды, `ORPHAN_GRACE_MS`), `PageDraft` сохраняет его текст отдельной страницей (документом) «Название (правки Имя, дд.мм чч:мм)»: вики `POST /wiki` у того же родителя, документ `POST /projects/{id}/docs` в том же проекте и режиме, затем `PATCH` с `before_id`, чтобы копия встала сразу за оригиналом (если переставить не вышло, копия остаётся в конце или первой, это не страшно). Оригинал остаётся с чужой версией, всплывает плашка на 9 секунд с названием копии. Нет связи: правки остаются, копия сохранится повтором, и только одна. Сервер отказал: плашка об ошибке, правки остаются, на странице ждёт обычный баннер. Человек ушёл, не выбрав на баннере: правки тоже уходят в копию. Разошлись только названия, а текст слился: копии нет, остаётся чужое название. Человек на странице: прежний баннер. За копию отвечает необязательный `saveCopy` в `DraftDeps`: без него (в тестах) всё как раньше.
- **Защита при закрытии (этап Н2).** Пока в окне есть неотправленный текст (`unsentCount()`), закрыть его молча нельзя. В браузере это `beforeunload` (вопрос задаёт сам браузер). В окне Tauri это `onCloseRequested`: окно не закрывается, неотправленное пробует уйти две секунды (`CLOSE_WAIT_MS`), и если не ушло, показывается окно «Есть неотправленные правки» с кнопками «Остаться» (и крестик, и Esc) и «Закрыть без отправки», после чего `destroy()`. Для этого в `app/src-tauri/capabilities/default.json` добавлено разрешение `core:window:allow-destroy`: без него библиотека не смогла бы закрыть окно, пока слушатель стоит. Проверено `cargo check`, но не вручную в окне.

- **Не проверено вручную:** окно Tauri (`npm run dev-app`): событие `offline`, `/healthz` через `tauri-plugin-http` и защита при закрытии (`onCloseRequested`, `destroy`). В браузерном режиме (тот же Chromium) и в тестах `tests/visual/offline.spec.ts`, `offline-copy.spec.ts` всё проверено.

- **Что где хранится.** Тема, полосы прокрутки, первый день недели и «Обновлять вживую» лежат на этом компьютере вместе с остальными настройками (`settings.ts`, Tauri store), на сервер не уходят. Профиль и пароль живут на сервере (`PATCH /me`, `POST /auth/password`).
- **Профиль.** «Сохранить» активна, только когда что-то изменено и имя не пустое; пробелы по краям убираются. После сохранения в сессии остаётся ответ сервера, список участников перечитывается сразу (свою же `user.changed` клиент пропускает по метке), у других клиентов он обновляется по событию. Если профиль поменяли на другом устройстве того же человека, `Workspace` подтягивает новое имя в сессию, как только пришёл свежий список участников (сверка только по списку, а не по сессии: сразу после своей правки сессия уже новая, а список ещё старый).
- **Смена пароля.** Клиент до отправки проверяет то же, что сервер (текущий указан, новый от 8 символов, повтор совпадает, новый не равен текущему: `password.ts`), но решает сервер. Неверный текущий пароль приходит как 400 `wrong_password`: клиент при любом 401 пытается обновить токен и при неудаче считает сессию потерянной, поэтому 401 тут нельзя. Успех: сервер отдаёт новую пару токенов, клиент запоминает её (`applyTokens`), человек остаётся в приложении. Другие устройства обновить вход уже не смогут и войдут заново, но токен доступа, выданный им раньше, действует до конца срока (до 12 часов): мгновенного отзыва нет, это решение владельца (отдельной кнопки «выйти на всех устройствах» тоже нет).
- **Заглушки.** «Приложение» (автозапуск, трей) и «Горячие клавиши» показывают «Скоро»; переключатели в них недоступны.
- **Иконки** у категорий (`TAB_ICONS` в `SettingsModal.tsx`) и у пунктов меню пользователя. Для «Доски» взята иконка `board` из макета, остальные (`user`, `palette`, `server`, `database`, `window`, `keyboard`, `info`, `gear`, `sun`, `moon`, `logout`) в макете отсутствуют: нарисованы в его стиле (24×24, обводка, скруглённые концы) по просьбе владельца и лежат в конце `components/iconPaths.tsx` под своим комментарием. У пункта «Тёмная/Светлая тема» иконка меняется вместе с названием: луна или солнце.
- **Тема.** Хранится `light`, `dark` или `system`; `useDark()` решает, какой класс ставить на `.app`. Быстрый пункт меню «Тёмная/Светлая тема» переключает от той, что видна сейчас, и записывает явную `light` или `dark`.
- **Первый день недели** меняет календарь (подписи дней, первая ячейка) и начало окна диаграммы Ганта. Фильтр «На этой неделе» не затронут: он считает семь дней вперёд, а не календарную неделю.
- **Обновлять вживую** выключено: сокет не открывается, точка связи на аватаре и строка состояния в меню скрыты, данные обновляются при открытии экранов. Включили: соединение поднимается сразу.
- **Полосы прокрутки.** Режим хранится атрибутом `data-scrollbars` на `<html>`. «Скрытые» — `scrollbar-width: none` и `::-webkit-scrollbar { display: none }`: полосы нет и места она не занимает, колесо и тачпад листают. «Тихие» — прозрачный ползунок, который показывается, пока над блоком курсор (`data-scroll-hover`) или блок только что прокрутили (`data-scrolling`, 0,9 секунды); обе пометки ставит `lib/scrollbars.ts`, и только в этом режиме. У самого окна ползунок появляется при прокрутке и когда курсор над ним. Особенности Chromium, из-за которых CSS именно такой (проверено по пикселям в `scrollbars.spec.ts`): стиль полосы окна берётся не с `html`, поэтому дорожку красит фон `:root`, а не `html::-webkit-scrollbar-track`; `:hover` в правилах `::-webkit-scrollbar-thumb` значит «курсор над самим ползунком», а не «над блоком», и срабатывает только в правилах без предка, поэтому наведение на блок делает JS, а общие `:hover` и `:active` стоят в файле последними, и правила «тихих» уравнены с ними по весу через `:where`.
- **Выход и окно настроек.** Окно закрывается, когда исчезает рабочее пространство (выход, потеря входа): иначе оно открылось бы само после следующего входа.
- **Не проверено вручную:** окно настроек в окне Tauri (`npm run dev-app`); в браузерном режиме (тот же Chromium) и в тестах всё проверено.

## Идентификатор и иконка

- **Идентификатор приложения:** `com.simptom.plexolab` (`app/src-tauri/tauri.conf.json`). После выпуска его менять нельзя: Windows посчитает приложение другим, настройки и вход пропадут.
- **Иконка (временная, можно заменить).** Сейчас используется `design/icon.png` (440×440), её копия лежит в `app/src/assets/icon.png`. Для хорошего качества `.icns` и крупных размеров нужна PNG 1024×1024 с прозрачным фоном. Чтобы заменить: положить новый файл на место `design/icon.png`, скопировать его в `app/src/assets/icon.png` и выполнить `npm --prefix app run tauri icon src/assets/icon.png`. Каталоги `icons/android` и `icons/ios` после этого удалить, мобильные сборки не нужны.

## Что нужно знать заранее

- **Локаль базы данных.** Поиск без учёта регистра (документы, файлы) делает Postgres через `lower()`. Чтобы он различал регистр русских букв, база должна быть создана с локалью, знающей Unicode (`ru_RU.UTF-8`, `en_US.UTF-8`; на Windows подойдёт `Russian_Russia.1251`). В локали `C` строчные и заглавные кириллические буквы считаются разными, и поиск «планирование» не найдёт «Планирование». Проверить: `select datcollate from pg_database where datname = 'plexolab'`.
- Макет в формате `.dc.html` открывается только внутри Claude. Claude Code читает его как текст. По скриншотам видно, как должно выглядеть на самом деле. Они сняты в Chromium с локальными шрифтами Manrope и JetBrains Mono, так же, как будет рендерить WebView2.
- **Прокси перед сервером и WebSocket.** Caddy (`reverse_proxy`) пропускает WebSocket без особых настроек. Соединение идёт часами, пауз молчания нет: сервер шлёт `ping` каждые 25 секунд, чего хватает против обрыва неактивных соединений на промежуточных узлах. Этап 10 это проверит на настоящем сервере.
- Скриншоты сравниваются в Chromium. На Windows Tauri использует WebView2 (тот же движок), поэтому внешний вид совпадёт. На macOS и Linux Tauri рисует через WebKit, возможны мелкие отличия.
- Текст интерфейса в макете русский. Меняется только если вы решите иначе.
