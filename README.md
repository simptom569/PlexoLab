# PlexoLab

Десктоп-приложение для небольшой команды разработки: канбан-доска, бэклог, модули, релизы и вехи, вики с файлами, документы (страница и холст), активность, ссылки команды. Клиент на Tauri 2 + React, бэкенд на Rust (axum) и PostgreSQL. Интерфейс повторяет макет из `design/`.

Правила проекта: `CLAUDE.md`. Этапы работы: `docs/PLAN.md`. Сейчас готовы этапы 0 (каркас), 1 (дизайн-система, AppShell и Sidebar), 2 (бэкенд: миграции, вход, сид), 3.1 (бэкенд доски: проекты, колонки, задачи, перенос, подзадачи, комментарии, метки), 3.2 (клиент доски) и 4 (бэклог, модули, вехи, релизы).

## Требования

- Rust stable (MSVC-тулчейн на Windows) и Visual Studio Build Tools с компонентом C++.
- Node.js 24 и npm.
- WebView2 (в Windows 11 уже есть).
- PostgreSQL 18 нужен бэкенду и его тестам (на этой машине стоит локально, база `plexolab`, пароль `postgres` — `dev`, только для разработки).

## Сервер

**Настройки.** Скопируйте `.env.example` в `.env` (файл в git не попадает). Сервер читает переменные окружения, `.env` подхватывается автоматически при разработке.

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | подключение к PostgreSQL (обязательно) |
| `JWT_SECRET` | секрет подписи токенов, не короче 32 символов (обязательно) |
| `BIND_ADDR` | адрес сервера, по умолчанию `127.0.0.1:8080` |
| `DATA_DIR` | папка файлов, по умолчанию `./data` (используется с этапа 5) |
| `CORS_ORIGINS` | откуда клиенту можно ходить в API, через запятую. По умолчанию адреса Tauri (`http://tauri.localhost` и др.) и Vite (`http://localhost:1420`) |
| `EXPOSE_OPENAPI` | `true`: отдавать схему API по `/api/v1/openapi.json`. По умолчанию выключено (в боевом режиме схема никому не нужна), в `.env` для разработки включено |
| `RUST_LOG` | уровень логов, по умолчанию `info`; в логе каждый запрос с временем ответа |

**Пользователи.** Публичной регистрации нет, пользователей создаёт администратор из командной строки. Пароль лучше передавать через стандартный ввод, чтобы он не попал в историю команд:

```powershell
'длинный-пароль' | cargo run --manifest-path server/Cargo.toml -- user add --email lena@example.com --name "Лена М." --role Frontend --admin --password-stdin
```

На сервере то же самое готовым бинарником: `server user add ...`. Через `npm run` команду с паролем из пайпа не запускайте: в PowerShell пайп заставляет запускаться `npm.ps1`, и он теряет аргументы.

Параметры: `--email`, `--name` (обязательно), `--role`, `--tone 0..4` (цвет аватара), `--admin`, `--password` или `--password-stdin` (не короче 8 символов). Миграции на пустой базе применяются сами.

**Смена пароля** (если сотрудник забыл или пароль скомпрометирован):

```powershell
'новый-длинный-пароль' | cargo run --manifest-path server/Cargo.toml -- user passwd --email lena@example.com --password-stdin
```

На сервере: `server user passwd ...`. Команда меняет пароль и сразу завершает все сессии этого человека, на каждом устройстве ему придётся войти заново. Токен доступа, уже выданный ранее, действует до конца своих 12 часов. Windows PowerShell 5.1 при передаче пароля через пайп добавляет в начало невидимый маркер, команды его вырезают сами.

**Демо-данные.** `npm run seed` заполняет пустую базу данными из `seed()` макета: 5 пользователей (пароль `dev`, вход `lena@example.com`), 3 проекта, 24 задачи, модули, вехи, релизы, вики, документы, файлы (записи без файлов на диске), ссылки и активность. Даты сдвигаются так, чтобы «сегодня» было реальной датой. Если пользователи уже есть, сид ничего не делает. `--reset` стирает все данные, поэтому его нужно запускать только на базе разработки.

**API.** Все ручки под `/api/v1`, проверка живости: `GET /healthz`. Схема OpenAPI: `server openapi --out файл.json` (сервер и база не нужны, так клиент получает типы), а при `EXPOSE_OPENAPI=true` ещё и `GET /api/v1/openapi.json`. Ошибки всегда в виде `{ "code": "...", "message": "..." }`.

| Ручка | Что делает |
|---|---|
| `POST /api/v1/auth/login` | вход по e-mail и паролю: токен доступа (JWT, 12 часов) и refresh-токен (30 дней) |
| `POST /api/v1/auth/refresh` | обмен refresh-токена на новую пару, старый перестаёт действовать |
| `POST /api/v1/auth/logout` | завершить сессию (удалить refresh-токен) |
| `GET /api/v1/me`, `GET /api/v1/users` | текущий пользователь, участники команды в порядке добавления (нужен токен, без него 401) |
| `GET /api/v1/projects` | проекты в порядке создания |
| `GET /api/v1/projects/{id}/board` | всё для первой загрузки доски: проект, колонки, все задачи (доска и бэклог) с метками и счётчиками подзадач, метки, модули, вехи |
| `POST /api/v1/projects/{id}/columns`, `PATCH`/`DELETE /api/v1/columns/{id}` | колонки: создать, переименовать, перекрасить, отметить «Готово», переставить (`before_id`), удалить (`?move_to=`, последнюю удалить нельзя) |
| `POST /api/v1/projects/{id}/tasks`, `GET`/`PATCH`/`DELETE /api/v1/tasks/{id}` | задачи: создать (номер `WEB-159` выдаётся в транзакции), прочитать целиком, изменить любые поля и перенести, удалить |
| `POST /api/v1/tasks/{id}/subtasks`, `PATCH`/`DELETE /api/v1/subtasks/{id}` | подзадачи |
| `POST /api/v1/tasks/{id}/comments` | комментарий от имени текущего пользователя |
| `GET`/`POST /api/v1/tags`, `DELETE /api/v1/tags/{id}` | метки (повторное создание той же метки без учёта регистра возвращает существующую) |
| `POST /api/v1/projects/{id}/modules`, `PATCH`/`DELETE /api/v1/modules/{id}` | модули: создать (ответственный — автор, статус «Запланирован»), изменить название, статус, ответственного, даты, заметку, удалить (задачи остаются без модуля) |
| `POST /api/v1/projects/{id}/milestones`, `PATCH`/`DELETE /api/v1/milestones/{id}` | вехи: название и дата |
| `GET`/`POST /api/v1/projects/{id}/releases`, `PATCH`/`DELETE /api/v1/releases/{id}` | релизы от новых к старым, каждый с чек-листом; новый получает четыре стандартных шага |
| `POST /api/v1/releases/{id}/items`, `PATCH`/`DELETE /api/v1/release-items/{id}` | шаги чек-листа: добавить в конец, переименовать, отметить, удалить |

Токен доступа передаётся в заголовке `Authorization: Bearer ...`. В базе лежит только sha256 refresh-токена. Остальные ручки из `docs/DATA-MODEL.md` (вики, файлы, документы, активность, ссылки) появятся на этапах 5–7, загрузка вложений задач на этапе 5.

**Бэклог, модули, вехи.** Отдельного списка бэклога нет: это задачи с `column_id = null` из ответа `GET /projects/{id}/board`, порядок и «На доску» делает тот же `PATCH /tasks/{id}`. Модули и вехи приходят в том же ответе, вместе с `tasks_total` и `tasks_done`: прогресс считает сервер (задача готова, если лежит в колонке с отметкой «Готово»; задачи из бэклога входят в «всего», но не в «готово»). Поэтому прогресс сам пересчитывается при смене колонки задачи.

**Лента активности** получает записи от модулей (категория `module`: создан, удалён, «переведён в «В работе»»), вех и релизов (категория `release`: создан, удалён, смена статуса, «отмечен шаг «…»»; шаг пишется только когда его отмечают, а не снимают). Переименования, даты и заметки в ленту не попадают.

**Перенос карточки** делается одним `PATCH /api/v1/tasks/{id}`:

| Тело | Что произойдёт |
|---|---|
| `{ "column_id": "<колонка>" }` | в конец этой колонки |
| `{ "column_id": "<колонка>", "before_id": "<задача>" }` | в эту колонку перед указанной задачей (она должна лежать в этой колонке) |
| `{ "before_id": "<задача>" }` | в своей колонке перед указанной |
| `{ "column_id": "<своя колонка>", "before_id": null }` | в конец своей колонки |
| `{ "column_id": null }` | в бэклог (так же, `before_id` работает внутри бэклога) |

Остальные поля можно слать в том же запросе: что не передано, не меняется, а `null` очищает необязательные поля (исполнитель, даты, модуль, веха). Позиции дробные: между соседями берётся среднее, а когда зазор меньше 1e-6, позиции всей колонки пересчитываются с шагом 1024. Все изменения доски идут по очереди внутри проекта, в ленту активности пишутся создание, удаление, перенос между колонками, комментарий и добавление PR, в той же транзакции.

**Миграции** лежат в `server/migrations` и являются источником правды о схеме. От `docs/DATA-MODEL.md` они отличаются только защитой и индексами: проверки значений (`tone`, `color`, `kind`, e-mail в нижнем регистре), уникальность метки без учёта регистра, индексы по внешним ключам, колонка `created_at` у refresh-токенов и колонка `seq` у проектов, меток, участников и модулей (порядок создания: так идут проекты в боковом меню, метки в панели задачи, исполнители в фильтрах и модули на своём экране, как в макете, а не по алфавиту). Если базу заполняли сидом до миграций `0007`–`0009`, выполните `npm run seed -- --reset`, чтобы порядок совпал с макетом.

**Тесты сервера** (`npm run test-server`) идут на настоящем Postgres: каждый тест получает временную базу `_sqlx_test_*`, которая удаляется после него. Нужен `DATABASE_URL` с пользователем, который может создавать базы.

### Визуальные тесты

Один раз: `npm --prefix tests/visual install`, затем `cd tests/visual && npx playwright install chromium`. Сервер разработки поднимется сам.

- **Сравнение с эталоном.** Область интерфейса снимается в окне 1440×900 и сравнивается с `design/screenshots` попиксельно. Допуск: меньше 0,5% отличающихся пикселей (`tests/visual/tolerance.ts`). Эталон снят в Chromium на Linux, там текст шире примерно на 4–8%, чем в Chromium на Windows. Поэтому строки текста (их прямоугольники берутся из DOM) в пиксельное сравнение не входят, сами тексты проверяются по DOM. Всё остальное (фоны, рамки, иконки, аватары, скругления, отступы) сверяется жёстко. Картинки с результатом лежат в `tests/visual/output/` (снимок, эталон, разница).
- **Снимки витрины и каркаса** лежат в `tests/visual/snapshots/` и привязаны к ОС (`-win32`).
- **Иконка в меню.** Вместо пунктирной заглушки эталона в боковом меню стоит иконка приложения, её квадрат 32×32 исключён из сравнения.

- **Экраны доски** (`board.spec.ts`, `board-drag.spec.ts`): виды «Доска», «Список», «Таблица», «Календарь», «Ганта», поповеры «Фильтры» и «Отображение», панель задачи и перенос (эталоны 01–08, 20, 21, 23), обе темы. Текст в полях ввода тоже закрывается маской. Таблицу сверяют построчно: в эталоне заголовок одной задачи переносится на вторую строку (текст шире), и всё ниже сдвигается; строки другой высоты пикселями не сравниваются, допустимо не больше двух.
- **Поведение доски** (`board-actions.spec.ts`): фильтры, поиск, «Отображение», виды, колонки, быстрое добавление, панель задачи, оптимистичность и откат при отказе сервера. Данные после каждого теста возвращаются к данным макета.
- **Бэклог, модули, релизы и вехи** (`work.spec.ts`): эталоны 09–11 и 22 (перенос строки бэклога) в обеих темах, перенос и порядок в бэклоге, «На доску», быстрый ввод, статусы и ответственные модулей, «Показать на доске», пересчёт прогресса модуля и вехи при переводе задачи в «Готово», вехи и релизы (добавление, даты, чек-лист, удаление с подтверждением) и плашка об ошибке. В эталоне 22 подсвечена строка, над которой браузер оставил указатель до начала переноса, у нас подсветка идёт за указателем, поэтому её фон исключён из сравнения.

## Клиент: доска

Код в `app/src/features/board/`:

| Файл | Что делает |
|---|---|
| `logic.ts` | чистая логика: фильтры, срок и просрочка, сортировка таблицы, ячейки календаря, окно Ганта (с тестами) |
| `cache.ts` | чистые изменения кэша доски для оптимистичных обновлений: перенос, правка, удаление колонки (с тестами) |
| `mutations.ts` | запросы на изменение: перенос, правки, колонки, подзадачи, комментарии, метки |
| `model.ts`, `BoardProvider.tsx` | загрузка доски и всё, что из неё выводится; контекст для экранов |
| `dnd.ts`, `DragProvider.tsx` | перетаскивание карточек, колонок и плашек календаря |
| `KanbanView`, `ListView`, `TableView`, `CalendarView`, `GanttView` | виды доски |
| `TaskDrawer.tsx` | правая панель задачи |

- **Оптимистичные обновления.** Перенос, правка полей, смена колонки, подзадачи и удаление показываются на экране сразу. Если сервер отказал, экран возвращается к прежнему состоянию. Когда на сервере не остаётся ожидающих изменений, доска перечитывается и берёт точные позиции. Создание (задача, колонка, комментарий, метка) ждёт ответа сервера, потому что номер `WEB-N` выдаёт он.
- **Перетаскивание.** `@dnd-kit/core` отвечает за захват указателя и копию под ним, а место заглушки определяется по элементу под указателем, как в макете: над карточкой выше или ниже середины, над колонкой в конец, над днём календаря. Бросок не над целью ничего не меняет, бросок на то же место запроса не отправляет. Клавиатурного переноса, как и в макете, нет: статус и колонку можно сменить в панели задачи.
- **Что хранится на компьютере** (не уходит на сервер): тема, страница, проект, вид, фильтры и «Отображение». Поиск, открытая задача и месяц календаря не сохраняются.

| `lib/useDraft.ts` | черновик поля: правится на месте, на сервер уходит по blur или Enter, а не на каждую букву |
| `lib/toast.ts`, `components/Toast.tsx` | плашка «Не удалось сохранить, изменение отменено», когда сервер отказал в любом изменении |

- **Плашка об ошибке** показывается на несколько секунд снизу по центру. В макете такого элемента нет, это единственное отступление от «один в один» (решение владельца): собрана только из переменных и размеров макета, новых цветов нет.
- **Удаление с подтверждением**, как в макете: первое нажатие меняет подпись на «Точно удалить?», второе удаляет. Подтверждение одно на весь экран: нажатие «Удалить» у другой карточки переносит вопрос на неё.
- **Новая веха и новый релиз** без даты получают срок «сегодня + 14» и «сегодня + 21» дней по часам этого компьютера, как в макете.

## Идентификатор и иконка

- **Идентификатор приложения:** `com.simptom.plexolab` (`app/src-tauri/tauri.conf.json`). После выпуска его менять нельзя: Windows посчитает приложение другим, настройки и вход пропадут.
- **Иконка (временная, можно заменить).** Сейчас используется `design/icon.png` (440×440), её копия лежит в `app/src/assets/icon.png`. Для хорошего качества `.icns` и крупных размеров нужна PNG 1024×1024 с прозрачным фоном. Чтобы заменить: положить новый файл на место `design/icon.png`, скопировать его в `app/src/assets/icon.png` и выполнить `npm --prefix app run tauri icon src/assets/icon.png`. Каталоги `icons/android` и `icons/ios` после этого удалить, мобильные сборки не нужны.

## Что нужно знать заранее

- Макет в формате `.dc.html` открывается только внутри Claude. Claude Code читает его как текст. По скриншотам видно, как должно выглядеть на самом деле. Они сняты в Chromium с локальными шрифтами Manrope и JetBrains Mono, так же, как будет рендерить WebView2.
- Скриншоты сравниваются в Chromium. На Windows Tauri использует WebView2 (тот же движок), поэтому внешний вид совпадёт. На macOS и Linux Tauri рисует через WebKit, возможны мелкие отличия.
- Текст интерфейса в макете русский. Меняется только если вы решите иначе.
